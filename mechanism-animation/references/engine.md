# 模板怎么改：结构、小工具、套路、坑、自测

模板是单个 HTML（`assets/template.html`），不依赖任何外部文件。脚本分四段：

| 段 | 内容 | 改不改 |
|---|---|---|
| **A** | `PAGE`、`MODULES`：模块、步骤、左边的文字、每步时长 | 改 |
| B1 | 时间轴、关键帧、SVG 小工具；按 `MODULES` 生成导航和模块页 | 一般不动 |
| **C** | 画面：有哪些对象、每一步怎么动 | 改 |
| B2 | 播放、翻页、导航、放大图、自动播放 | 一般不动 |

换题目时 HTML 里要改的 5 处（模板里都还是「缓存」那个示例的内容）：

1. `<title>`；
2. 开头页 `#top`：小字、大标题、一句话、每个模块一张预告卡片；
3. `<svg id="fig">` 的 `aria-label`（一句话说这张图演的是什么）；
4. 结尾页 `#where` 的几行：第一行先回答「所以呢」（效果、对读者意味着什么），再写现状（做到哪了）、代价和限制；数字写出处；
5. 结尾页页脚：`更新：年月 · 对着哪个版本的代码核的`。

结尾页的「全过程一览」（`#recap`）是脚本按 `MODULES` 自动生成的，每步一行，不用手写。模块顺序变了，记得开头页的卡片也跟着改。

## A 段：内容

```js
var PAGE={ mark:"缓存原理", end:{nav:"小结", rail:"小结"} };   // 顶部导航左边的名字；结尾页在导航和左侧目录里的名字
var MODULES=[
 { id:"m1",                 // 模块页的 id（锚点），全页唯一
   nav:"1 没有缓存",        // 顶部导航上的字
   rail:"没有缓存",         // 左侧竖排目录上的字（短）
   meta:"每次都查库",       // 模块标题上面那行小字
   title:"没有缓存",        // 模块大标题
   line:"每个页面要数据，都去数据库读一次。",   // 标题下一句话
   steps:[
    { id:"db",              // 步骤 id：画面里用 T("db", 0.4) 定时间，全页唯一
      t:"数据在数据库里",   // 步骤标题 = 这一步讲的那件事
      dur:2200,             // 这一步动画的毫秒数，缺省 2600
      lead:"先看最底下：……",            // 一句话
      pts:["……**加粗**……", "`代码`", "{{4 KB}} 这样包起来的词不会被拆成两行"] }   // 要点，≤ 3 条
   ]}
];
```

时长怎么给：只有淡入的 1800–2200；有一次移动的 2600；一连串先后发生的 4000–6500。读者嫌「太急」就加时长，嫌慢就减，不用动关键帧。

## 时间轴

- 第 k 步（从 0 数）占时间轴 `[k, k+1]`。**画面里一律写 `T("步骤 id", 比例)`**，比例 0–1 是这一步走到哪了。`T("db")` = 这一步开始，`T("db", 1)` = 结束。
- 好处：插入步骤、调整步骤和模块的顺序，画面里的时间都不用改。
- 时间 0 是第 1 步开始之前的画面。
- **硬规则：一步里的动作必须在这一步结束前停住。** 淡入淡出占 0.1（常量 `FD`），所以淡入最晚从 0.88 开始（自测在结束前 1.5% 处取样，正好排在 0.9 的淡入那时还差一点没完，会被判成「还在动」）。淡出可以排在 `T(id, 1)`，它会在下一步开头完成，这是正常的「上一步的箭头在下一步开头退场」。
- 报错里的时刻是时间轴上的数：整数部分是第几步（从 0 数），小数是这一步里的比例。`2.92` = 第 3 步的 92%。

## C 段：小工具

| 函数 | 作用 |
|---|---|
| `frame(x, y, w, h, 标题, 小字, 层, 样式)` | 带标题的框，返回 `<g>`。框里的东西往这个 g 里加；整组淡入淡出、变淡都对这个 g 做 |
| `arrow(路径 d, a, b, out)` | 橙色带箭头的线，a→b 画出来，`out` 时刻退场（不给就一直在） |
| `notes([几行字], x, y, a, b, 样式)` | 几行说明逐行出现（每行晚 0.04），`b` 时刻一起退场（不给就一直在）。左对齐；返回这几行的 `<text>` 数组，要居中就对它们 `setAttribute("text-anchor","middle")` |
| `legend([[名字, 颜色], …], x, y)` | 图例，自己按字宽排开 |
| `show(节点们, a)` | a 时刻淡入，之后一直在 |
| `span(节点们, a, b)` | a 淡入，b 开始淡出。b 离 a 不到 0.1 时淡入会被压短 |
| `fade(节点们, keys)` | 自己写透明度关键帧：`[[0,{o:0}],[a,{o:1}],[b,{o:.35}]]` |
| `moveBox(rect, keys)` | 矩形按 `{x,y,w,h,o}` 关键帧移动 / 变形 |
| `drawIn(path, a, b, out)` | 任意一条线从起点画到终点（`arrow` 就是它加了样式） |
| `add({keys, draw, ease})` | 通用：任意属性的关键帧，`draw(v)` 每帧拿到插值后的值 |
| `el(tag, attrs, parent)` / `txt(cls, x, y, 文字, parent, extra)` | 建 SVG 元素 / 文字 |
| `mix(a, b)` / `box(rect, v)` | 合并两个对象（`mix(位置, {o:1})`）/ 把 `{x,y,w,h}` 写到矩形上 |

文字的 class：`fx-t` 标题（15）、`fx-s` 小字（14）、`fx-note` 说明（14，加 `act` 橙 / `blue` / `red`）、`halo` 白描边（压在线上时用）。**不要用小于 14 的字号。**

关键帧 `[[时刻, {属性}], …]`：时刻从小到大（写反会直接报错）；没写的属性沿用前一帧的值；数字属性在两帧之间按缓动插值（缺省「两头慢中间快」，`fade` 用淡入淡出曲线）。

三层：`BG`（底）、`MID`（框和内容）、`FG`（箭头、飞行的块、说明）。后建的在上面。动作色是常量 `ACT`。

**一个节点的透明度只能由一处管。** `show` / `span` / `fade` / `moveBox` / `drawIn` 对同一个节点用了两个，会直接报错。要「先淡入、后来变淡」，写成一条 `fade` 关键帧；或者在外面再包一层 `<g>`，里外各管一次。

模板没有的封装（带字的色块、一行一行的格子），在 C 段开头自己写成小函数（示例里的 `block()`、`slot()`），别在每个对象上重复写属性。

## 画面套路（模板示例里都有）

**依次出现**：给每个对象一个 `show(..., T(id, 比例))`，比例按因果顺序排。一组同类的东西用 `b = 0.06 + i*0.3` 这种写法错开。

**同一个东西从 A 飞到 B**：
```js
var tk=el("rect",{rx:5,fill:C.data},FG);
moveBox(tk,[[0,mix(A,{o:0})],[T("s",.17),{o:0}],[T("s",.19),{o:1}],[T("s",.29),mix(B,{o:1})]]);
```
先在 A 处淡入（2% 就够），再移动到 B，留在 B。之后要消失就再加两帧 `{o:1}` → `{o:0}`。

**请求 / 读取的箭头**：`arrow(d, 起, 止, T(id,1))`，这一步结束时退场。

**多个请求读同一份**：几条路径写成 `M起点 V200 H目标x V目标y`，共用后半段，看起来汇成一条；再 `span([圈], …)` 给目标加橙圈。

**计数 / 数字跳变**：`add` 里用相邻两帧（差 0.01）让数字「跳」，`draw` 里 `textContent=Math.round(v.n)`。

**占用条变长变短**：一个 `add` 管所有段的宽度（`{a:60,b:0,…}`），`draw` 里从左到右依次摆。要「飞过去再缩」：飞行的块先落到条上要缩掉的那一截（落点用条的实时位置算），全部落定后再让那一截宽度变 0。

**重置 / 「从头看」**（同一批东西换一种做法再走一遍）：在这一步开头（比例 0–0.1）把上一步留下的数据块淡出、计数跳回 0；新出现的东西稍后淡入；配一句橙色小字「换成 X，从头看」，这一步结束时退场。示例的 `fill` 那一步就是这样写的。

**换场景**（整组东西换掉）：把一组对象放进一个 `<g>`，对 `<g>` 做淡出；新场景的对象在同一步里稍后淡入。旧场景里的对象变成新场景里的对象时（容器长成虚机），用一个过渡框 `moveBox` 从旧位置变到新位置，再淡出。

**整组变淡表示「这部分用不上了」**：这组东西的 `<g>` 用一条 `fade`，最后一帧降到 0.35 左右（示例里的数据库）。要让好几组在同一刻变淡，写个小函数生成这条关键帧，别逐个手抄。

**连线怎么走**（被问「为什么会有这种拐角」之后补的）：端点落在两个框**相对的边**上，不要瞄着对方框的中心；两框高度有重叠就画一条 `H` 直线；要拐就先定一个拐点变量（如 `var PX=…`，避开文字），线写成 `M起点 V拐点y H终点x` 一个拐角；**沿这条路走的数据包、红线、虚线共用同一组拐点**，别各算各的。绕开障碍的 U 形最多两个拐角；`check.js` 的 bends 项拦小折弯（短于 12）和三个以上的拐角，确实要这么走的线标 `data-route-ok`。

**框的嵌套**：画之前列一张「对象 → 它真实所在的网络空间 / 容器 / 进程 / 服务」表，照表决定谁装在谁里面。独立的容器或进程（sidecar、代理）画成并列的框，不画进业务容器里；外框写清它是什么（「某个容器组的网络空间」），框名用读者的叫法。

**说明文字放哪**：两种位置，全页固定。一步一句的结论，放在两排东西之间的空带上，居中、加 `halo`；细节和数字出处，放在画布一角固定的小注区，每步 2–4 行，用 `notes()`，只在这一步显示就给 `b`。

## 坑

- **多写一帧会把位置钉住**。`[T(id,.2),{hl:0}]` 这种只想改一个属性的帧，会把前一帧的 `x,y,w,h` 一起带过来，等于在这个时刻把位置固定住，对象晚出发、和它的父框脱节。只改颜色 / 透明度时另开一个 `fade` / `add`，不要塞进位置的关键帧里。
- **父框和里面的东西要同时刻动**。给它们标 `data-box="名"` / `data-in="名"`，`check.js` 的 contain 项会在整段时间轴上逐帧查「里面的东西在不在框里」。只给「应该一直待在某个框里」的东西标（框里的字、格子、会跟着框一起缩放的内容）；在框之间飞来飞去的块不标。页面里一个标记都没有时这一项是 SKIP，不算没过。
- **透明度用 `style.opacity`**，整组淡入淡出就对 `<g>` 做，不要逐个元素重复写。祖先和自己都设了透明度会相乘。
- **文字压在线上**：加 `halo`。两条说明放同一位置轮流出现时，前一条的淡出和后一条的淡入不要重叠（中间隔 0.1 以上）。
- **画布 1000 × 640**，所有东西留在里面；`check.js` 的 canvas 项会查。
- **字号**：图里最小 14 个画布单位。图在 1280 宽的屏上缩到约 0.8 倍，14 才有 11px。嫌挤先删内容，不要缩字。
- **步骤 id 写错**会在加载时直接抛错（`T()：没有这个步骤 id`），打开控制台看。
- **别在 C 段里读写 B2 段的变量**（`target`、`section`、`p`）；画面只应是时间的函数。
- **手机宽度**：图固定在上方 44vh，文字在下面，靠「上一步 / 下一步」按钮和左右轻扫。画面太密时手机上会很小，这是已知的取舍。（可选的改进：手机上把镜头裁到当前这一步用到的那一块，而不是整图缩小；成本高，读者主要用手机看时才值得做。）
- 页面只做了浅色模式（SVG 颜色写死）。
- **用脚本拼接 / 替换 C 段时**（大改画面常这么做）：先留备份（`anim_C.v1.js`…），切片的起止下标要断言 `start < end`、各段不重叠；拼完 `grep -c 'var <对象名>='` 看有没有对象被定义了两次。11-18 拼接下标写反（`j < i`），一整段场景被复制了一份，图例互相压住——`overlap` 项报了，但要看截图才知道是重复而不是排版问题。

## 自测：scripts/check.js

```bash
node scripts/check.js <页面.html> <截图目录>
```

十项：`errors` `still` `overlap` `canvas` `contain` `wheel` `text` `mobile` `fontsize` `bends`，各自含义见脚本文件头。每项给 PASS / FAIL / SKIP，有 FAIL 退出码为 1。`errors` 报错时会带上出错的行号。

跑完看截图目录，**逐张看**：
- `step-NN.png` 每一步结束时的图：该在的东西在不在、不该在的走没走、单独看说不说得通、和上一张比有没有看得见的差别；
- `mid-NN.png` 每一步走到一半：飞行的块走的路线对不对、有没有穿过别的东西；
- `page-NN.png` 那一步的整页（1366 × 768）：左边文字和图对不对得上、挤不挤；
- `hero.png`、`mobile.png`。

依赖：Node 18 以上和 playwright。第一次用先装（装在哪都行，脚本先按模块名找）：

```bash
npm i playwright && npx playwright install chromium
```

脚本找不到时，用环境变量指给它：`PLAYWRIGHT_PATH=<node_modules/playwright 的路径>`、`CHROMIUM_PATH=<chrome 可执行文件>`。

耗时：4 步的页面约 1 分钟，12 步约 3 分钟；浏览器吃几百 MB 内存。**经 Agent 的命令行工具跑时，把这条命令的超时设到 5 分钟**（常见的缺省值 2 分钟不够，会拿到空输出），或者放后台跑、等它结束。

脚本查不了的，要自己看、自己想：
- 讲法对不对（顺序、有没有没交代的东西、相邻两步像不像、终态单独看说不说得通）；
- 动画中途的细节（脚本每步只截一张中途的图）。怀疑中途有问题，用 `__anim.render()` 在这一步里取十来个时刻截图看；
- 事实对不对。

改完任何东西都重跑一遍，哪怕只改了字：文字变长会把左栏顶出屏幕（`text` 项）。汇报自测结果时写明查的是什么（「10 项无 FAIL，step / mid 截图逐张看过」），不要只说「查过了」。
